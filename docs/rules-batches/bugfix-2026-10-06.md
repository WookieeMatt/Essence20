## 1. Dino Thunder Grid Powers - fixed

Real: the three Uses paid (Boost pool / Personal Power) and set `flags.essence20.d1DinoThunderActive` plus fired
`essence20.dinoThunderActivated`, which nothing read or listened to. The power effects live in
`ranger-form-perks.mjs` and key on the `zord1Dino` state. The power pick also used two flags: the Form's own
`zord1DinoPower` and a second picker's `dinoThunderPower`.

- `module/items/forms/ranger-form-perks.mjs`: the Form Use's body is now `activateDinoPower(actor, perk, power,
  {pay, spend})`, exported. The Form's own Use calls it. `pickDinoPower(perk, exclude)` is exported and can leave
  out powers.
- `module/items/forms/dino-thunder-grid-powers.mjs`: one flag (`zord1DinoPower`) on the Form Perk and on the Extra
  item. Every pick goes through the Form's picker, so picking Ptera Scream grants its weapon. Activating runs
  `activateDinoPower` for each power, paying the 1 Personal Power once: from the Boost pool when that's allowed,
  else Personal Power. Replication's extra point is regular Personal Power. The Uses now pass the action-economy
  `pay` along. A mimicked power (White Ranger) never uses the Boost pool. Book p.57: on morphing with the Extra power,
  the `zord1Dino` state is cleared, and so is the Invisibility status if it was on. The dead flag and hook are gone.
- A Dino Thunder Form picked before today keeps `zord1DinoPower`, because the Form's own createItem picker always
  wrote that flag. An Extra power picked under the old `dinoThunderPower` flag is asked again (v6 is unreleased).
- Tests: `module/items/tests/ranger-forms-megafauna.test.js` ("Dino Thunder Boost / Extra activate the real Form
  powers"): the Boost Use sets the real state (Tricera Skin +5 Toughness, Intangibility) and pays once from the pool.
  With the pool empty, Extra pays 1 Personal Power for both powers. `armor-gear-data-rules.test.js` moved to the one
  flag.

## 2. Fighting Style Careful / Defense - fixed

Real: `documents/actor.mjs#_prepareDefenses` adds Careful (+2 in cover) and Defense (+1 in armor) to
`defenses.total`. `getDefenseValue` reads that total, and `dice.mjs` then added the same bonuses again. The sheet
total is kept; the dice.mjs double is removed (`module/dice.mjs`, per-target difficulty).
Test: `module/dice.test.js` "Careful / Defense": the attack's difficulty equals the target's Defense total. The
actor.test.js sheet tests are unchanged.

## 3. Augur - fixed

Real: `ramConeAltAttack` matched Augur too, and dice.mjs reads it for both Armor Piercing and Anti-Tank. Now
`ramConeAltAttack` is Ram Cone only. The new `augurAltAttack` (Alt Mode Flyby/Ram/Bash) feeds only the Armor
Piercing check (`module/mechanics/combat/weapon-traits.mjs`, `module/dice.mjs`).
Test: `module/mechanics/vehicles/vehicle-upgrades.test.js` "Augur's Alt Mode attacks get Armor Piercing only".

## 4. Engine `heal` and Defeated - fixed (engine)

Real: `items/healing/heal-skill-test.mjs#applyHealSkillTestResult` clears Defeated after a real-Health heal; the
rules engine's `heal` step didn't. `module/rules/steps.mjs` `heal` now does the same for real Health: if the actor
was Defeated and Health is above 0 after the heal, Defeated is cleared (through the relayed write).
Temporary Health doesn't clear it, as before.
Test: `module/rules/bugfix-1006.test.js` "heal step".

**Nano-Med Mastery (left, needs its converter):** the old `team-buffs.mjs` heal never cleared Defeated, although
its notes say "bringing back the Defeated". The round-14 conversion now in its pack file heals with
`updateActor add system.health.value`, not the `heal` step, so it still doesn't clear Defeated. Switching that
step to `{do: 'heal', to: 'allies+self:60', amount: 2}` would match the notes. It's a convert item, so I didn't
touch it.

## 5. Exploit Weakness - fixed

Real: `exploitWeaknessMarked` was a bare `true`, never cleared, and dice.mjs let any roller ignore the marked
target's armor. Book (PR CRB p.57): the marker and their teammates, until the end of the scene. The mark is now
`{sceneEpoch, by}` and only counts while the Scene Clock's scene is unchanged. It applies to the marker, or to an
attacker on the marker's side (`items/shared/sides.mjs#sameSide`). An old bare `true` doesn't count. Files:
`module/items/attacks/exploit-weakness.mjs`, `module/dice.mjs` (reader passes the attacker; the marking passes the
roller).
Tests: `module/items/attacks/exploit-weakness.test.js` (scene end, marker / teammate / the target's side),
`module/dice.test.js` "a teammate of the marker ignores the armor; the target's own side doesn't".

## 6. Didn't Even Feel It - fixed

Real: the once-per-encounter use was checked on `renegade` (the holder, which is the driver when Racer Abandon
redirects) but marked on `target` (the vehicle), so it was never used up. It's now marked on `renegade`
(`module/chat.mjs`).
Test: `module/chat.test.js` "Didn't Even Feel It redirected by Racer Abandon is spent on the driver who holds it".

## 7. Expertise source lookup - fixed

Real: `_hasExpertiseDownshiftImmunity` read only `_stats.compendiumSource ?? rulesSource`, so a copy with only
`flags.core.sourceId` (Role-granted) wasn't recognised. It now checks all three sources, as `_actorHasPerk` does
(`module/dice.mjs`).
Test: `module/dice.test.js` "true for a copy that carries its source only in flags.core.sourceId".

## 8. Gang Up - fixed

Real: `getAllNearbyTokens(target, 5)` includes the attacker's own token, so a Psycho Path attacker next to its target
qualified itself. Book: "another" being on a Psycho Path. The attacker (same actor or same uuid) is now excluded
(`module/dice.mjs`).
Test: `module/dice.test.js` "the attacker itself next to the target doesn't count".

## 9. Augmented Combat / Codename Jolt - fixed

Real: both toggled `augmentedCombatActive`. Codename Jolt now has its own `codenameJoltActive` flag. The attack's
↑1 applies while either is on (the same effect, not stacked: the total with both on is what the shared flag gave).
Files: `module/items/attacks/augmented-combat.mjs`, `module/mechanics/characters/power-use.mjs`.
Tests: `module/items/attacks/augmented-combat.test.js`, `module/mechanics/characters/power-use.test.js`.

## 10. Temperamental - fixed

Real: `perkGrantedTraits` added Temperamental for any weapon with `flags.essence20.customized`, and the
`TRAIT_PERK.weaponCustomizer` key its comment pointed at was unused. It now also needs the weapon's holder to have

## 11. Kitted Out / Pinpoint / Manifest Enhancement / Command & Control - fixed

- **Kitted Out** (real): `kits.mjs#useKit` offered "set Specialization" on every kit to everyone. Changing a set
  kit's Specialization now needs Kitted Out. Setting up a generic kit (no Specialization yet, or a Skill Kit with no
  Skill) is still open to anyone, since that's how a generic kit gets set up. A kit with nothing to offer returns
  without an empty dialog. Test: `module/mechanics/resources/kits.test.js`.
- **Pinpoint** (real): `riderDialogFlags` offered `pinpointMax` on every non-melee attack. In combat it now needs
  the Aim action (`action-economy.mjs#isAiming`). Out of combat there's no action ledger, so it's still offered.
  The economy is a namespace import because several suites mock that module.
  File: `module/mechanics/combat/target-riders.mjs`. Test: `module/mechanics/combat/target-riders.test.js`.
- **Manifest Enhancement** (real): no limit. It's now once per round
  (`perks.mjs#hasUsedThisRound/markUsedThisRound`, flag `manifestEnhancementLastRound`): marked in
  `grants.mjs#manifestEnhancement` after the upgrade is attached, checked in `grant-uses.mjs#canUseGrant`.
  Not limited out of combat. Test: `module/mechanics/resources/grants.test.js`.
- **Command & Control** (real): the rank-gate bypass had no range check. Book p.50: both within 100 feet of each
  other. It's now refused when both are placed and more than 100 ft apart. An unmeasurable distance isn't a refusal,
  as with the rest of Lend Assistance. File: `module/mechanics/actions/lend-assistance.mjs`.
  Test: `module/mechanics/actions/lend-assistance.test.js`.
